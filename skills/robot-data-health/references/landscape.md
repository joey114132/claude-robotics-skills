# Robot Data Health Landscape — verified snapshot
**Verified: 2026-10-12.** Entries were confirmed against live sources on this date — re-verify anything before relying on it if this snapshot is more than ~6 months old.

## Recording and storage
- **rosbag2** — the ROS 2 record and playback tool, used as `ros2 bag`. The repository provides two storage plugins, `mcap` and `sqlite3`, and the default is `mcap`. Verbs listed: burst, convert, info, list, play, record, reindex. Compression is an option on `record` (`--compression-mode`, `--compression-format`) and a YAML key in the `--output-options` file, and the only compression format listed is `zstd`. Status: maintained. Source: https://github.com/ros2/rosbag2
- **rosbag2_storage_mcap writer presets** — the MCAP storage plugin takes a YAML file of `mcap::McapWriterOptions` via `--storage-config-file`, or a preset via `--storage-preset-profile`. `fastwrite` (no chunking, no summary CRC) maximizes write throughput, but its README says that using such files as long-term storage is not recommended, and that some features will not work when reading MCAP files without a message index. `zstd_fast` disables CRC calculation. `zstd_small` writes 4 MB chunks at the highest zstd ratio and can be resource-intensive to write, so the README suggests post-processing with `ros2 bag convert`. Status: maintained. Source: https://github.com/ros2/rosbag2/tree/rolling/rosbag2_storage_mcap
- **MCAP file format** — "a modular container file format for recording timestamped pub/sub messages with arbitrary serialization formats". The optional summary section holds a Chunk Index record for every chunk, and Message Index records locate messages inside a chunk by timestamp. CRC32 fields exist in the footer, chunk, attachment and DataEnd records, and for chunks and attachments a value of zero means CRC validation is not performed, so a zero CRC is unchecked data rather than verified data. Libraries cover C++, Go, Python, JavaScript/TypeScript, Swift and Rust, MIT licensed. Status: maintained. Source: https://mcap.dev/spec — Source: https://github.com/foxglove/mcap
- **MCAP ROS 2 guide (db3 conversion)** — recording to MCAP means setting the rosbag2 storage ID to `mcap`. `mcap convert` reads message definitions embedded in a `.db3` file, but bags recorded before ROS 2 Iron have no embedded definitions and must go through `ros2 bag convert` with the original workspace sourced. The page warns that CLI conversion may still produce different results from recording with the plugin directly. Status: maintained. Source: https://mcap.dev/guides/getting-started/ros-2

## Inspection and validation tools
- **mcap CLI** — 15 subcommands, including `info` (summary statistics), `doctor` ("Check an MCAP file structure"; the page does not list which checks it runs), `recover` (rebuilds a readable copy of a corrupt or truncated file, exit code 0 if all records were recovered, 3 if lossy, 1 if nothing recovered), `du` (byte usage statistics for records), `list`, `cat`, `filter`, `merge`, `sort`, `compress`, `decompress` and `convert` (ROS 1 `.bag` and ROS 2 `.db3` to MCAP). Status: maintained. Source: https://mcap.dev/guides/cli
- **rosbags** — "Pure Python library to read, modify, convert, and write rosbag files", Apache-2.0, repository created 2021-05-16, topic tags include rosbag1, rosbag2, mcap and cdr. The page does not state whether a ROS installation is required, so check the README before using it on a machine without ROS. Status: maintained. Source: https://gitlab.com/ternaris/rosbags

## Review and visualization
- **Foxglove** — commercial robotics data platform that reads MCAP and ROS bag recordings from the app, a cloud data platform or remote HTTP servers, and also offers live connections. Its Plot panel charts numeric topic fields against message timestamp, where for recorded files the timestamp is when the message was originally recorded. The Topics sidebar shows each topic's data type, message encoding and message rate, though message frequency and count are not available for data streamed from Foxglove Data Platform. The Image and 3D panels strongly prefer graphics acceleration. A free sign-up exists, pricing details are on a separate page. Status: commercial. Source: https://foxglove.dev/ — Source: https://docs.foxglove.dev/docs/visualization — Source: https://docs.foxglove.dev/docs/visualization/panels/plot
- **Rerun** — "the data layer for physical AI": logs multi-rate multimodal data (images, point clouds, transforms, time series, joint states, video), renders it in sync in a viewer, and lets recordings be queried with dataframes or SQL. Core written in Rust with Python, Rust and C++ SDKs, dual-licensed Apache-2.0 and MIT. The README warns "Expect breaking changes!". A commercial Rerun Hub is in development and limited to design partners. Status: maintained. Source: https://github.com/rerun-io/rerun
- **PlotJuggler** — time-series and XY plotting with multimodal panels, Mozilla Public License 2.0. File inputs listed: CSV, MCAP, Parquet, PX4 ULog, LeRobot, MP4, PCD and PLY. Live inputs include ROS 2, MQTT, ZeroMQ, UDP, WebSocket bridges, WebRTC and Lab Streaming Layer. Loaders and streamers install from File, Marketplace. Status: maintained. Source: https://github.com/facontidavide/PlotJuggler

## Learning dataset formats
- **LeRobotDataset v3.0** — tabular state, action and timestamp data in Apache Parquet, camera frames concatenated into per-camera MP4 shards, and metadata under `meta/` (`info.json` schema and FPS, `stats.json` mean/std/min/max, `tasks.jsonl`, chunked `episodes/` Parquet with per-episode offsets). Many episodes share one file, so episode boundaries come from metadata, not filenames. The docs warn that `dataset.finalize()` must be called after recording, otherwise Parquet footers are not written and the files are corrupt. Included in `lerobot >= 0.4.0`, and `StreamingLeRobotDataset` reads from the Hub without a local copy. The main repository lists tools to delete episodes, split, add or remove features and merge datasets, and is Apache-2.0. Status: maintained. Source: https://huggingface.co/docs/lerobot/lerobot-dataset-v3 — Source: https://github.com/huggingface/lerobot
- **RLDS (Reinforcement Learning Datasets)** — episodic data that can be loaded with TensorFlow Datasets: a dataset is a `tf.data.Dataset` of episodes, each holding a `tf.data.Dataset` of steps, with mandatory `is_first` and `is_last` step flags and optional observation, action, reward, `is_terminal` and discount. The repository includes a library for manipulating RLDS datasets; EnvLogger and RLDS Creator are linked as separate projects. The repository was archived by its owner on 2025-11-29 and is read-only. Status: archived. Source: https://github.com/google-research/rlds
- **Open X-Embodiment** — cross-robot dataset collection built from 22 robots at 21 institutions with 527 skills, released in standardized formats along with the RT-X models. The arXiv listing has about 294 authors and was last revised in May 2025 (v9). Status: research. Source: https://arxiv.org/abs/2310.08864

## Causes of gaps and offsets
- **ROS 2 DDS tuning guide, IP fragmentation** — on lossy links (typically WiFi), a UDP sample missing one IP fragment leaves the other fragments filling the receiver's kernel reassembly buffer, and the connection can hang for about 30 s, the default reassembly timeout. Switching to best-effort QoS reduces traffic but does not remove the symptom. The guide lists `net.ipv4.ipfrag_time` (default 30 s, example value 3 s) and `net.ipv4.ipfrag_high_thresh` (default 262144 bytes, example value 134217728 bytes). The guide says `ipfrag_time` is global to all incoming fragments, and that the threshold would likely have to be significantly high to hold all data received within the `ipfrag_time` window. A recording of such a stall shows as a gap in a large-message topic (images, point clouds) while small topics continue. The raw source for the Jazzy guide was read; the rendered docs.ros.org page returned an access-denied bot-protection page to the fetcher. Status: maintained. Source: https://raw.githubusercontent.com/ros2/ros2_documentation/jazzy/source/How-To-Guides/DDS-tuning.rst — Source: https://docs.ros.org/en/jazzy/How-To-Guides/DDS-tuning.html
- **chrony** — NTP implementation with the daemon `chronyd` and the CLI `chronyc`, GPL-2.0. The project states that with hardware timestamping or a hardware reference clock, sub-microsecond accuracy may be possible. Its `refclock PHC` driver takes a PTP clock device or the network interface name as a time source, and its comparison page marks hardware RX and TX timestamping as supported on Linux. Machines that sync to different sources, or never converge, produce header-stamp offsets between hosts in a multi-computer recording. Status: maintained. Source: https://chrony-project.org/ — Source: https://chrony-project.org/doc/latest/chrony.conf.html — Source: https://chrony-project.org/comparison.html
- **linuxptp** — Linux implementation of IEEE 1588 Precision Time Protocol with hardware and software time stamping through `SO_TIMESTAMPING`, ordinary, boundary and transparent clock roles, UDP/IPv4, UDP/IPv6 and raw Ethernet transport, and IEEE 802.1AS-2011 as an end station. The page notes that `ptp4l` needs the `-S` option on an interface that supports only software time stamping. Use it where chrony over NTP is not tight enough between robot computers. Status: maintained. Source: https://linuxptp.sourceforge.net/
