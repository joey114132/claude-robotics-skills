# Robot Arm Manipulation Landscape — verified snapshot
**Verified: 2026-10-02 (changed entries and link fixes; rest 2026-08-05).** Entries were confirmed against live sources on this date — re-verify anything before relying on it if this snapshot is more than ~6 months old.

## IK solvers
- **TRAC-IK** — hybrid IK solver (KDL Newton-based extension + SQP nonlinear optimization run concurrently) that handles joint limits better than plain KDL; an optional drop-in MoveIt kinematics plugin (KDL remains MoveIt's default; enable by setting `kinematics_solver: trac_ik_kinematics_plugin/TRAC_IKKinematicsPlugin` in kinematics.yaml and adding `<depend>trac_ik_kinematics_plugin</depend>` to package.xml). The core library is built on KDL and is not thread safe, so do not run multiple TRAC-IK library instances in one process (upstream README says the MoveIt plugin has been thread safe since v1.1.2). Status: maintained (upstream traclabs/trac_ik has ROS 2 branches jazzy, kilted and rolling, last push 2026-06-02). Source: https://github.com/traclabs/trac_ik (MoveIt how-to: https://moveit.picknik.ai/main/doc/how_to_guides/trac_ik/trac_ik_tutorial.html)
- **Pink** — Python differential/task-space inverse kinematics built on Pinocchio + QP solvers; define weighted tasks, get joint velocities. Status: maintained (v4.4.0 released 2026-09-09, active CI). Source: https://github.com/pink-kinematics/pink
- **ikpy** — pure-Python universal IK library; imports URDF/MJCF directly, has an experimental JAX backend as of v4 (requires Python 3.10+). Status: maintained. Source: https://github.com/Phylliade/ikpy

## Motion planning frameworks
- **MoveIt 2** — the standard ROS 2 manipulation stack (planning, perception, execution); pluggable planners with OMPL as the default backend. Status: maintained, PickNik-led, ~9.5k commits, multi-distro CI (Rolling/Jazzy/Humble). Source: https://github.com/moveit/moveit2
- **MoveIt Task Constructor** — hierarchical multi-stage manipulation planner built on MoveIt 2; composes planning stages (for example pick, move, place) in sequential or parallel containers and ships a pick-and-place tutorial. Status: maintained (ros2 branch tracks MoveIt 2 `main`, humble branch for Humble; last push 2026-09-10). Source: https://github.com/moveit/moveit_task_constructor
- **OMPL (Open Motion Planning Library)** — sampling-based planning core (RRT/PRM family and variants) used underneath MoveIt and other stacks. OMPL 2.0.0 (2026-04-06) rewrote the Python bindings (`pip install ompl`), added VAMP (Vector-Accelerated Motion Planning, which uses SIMD to speed up forward kinematics and collision checking) as an optional backend (the release notes cite planning speeds up to 25 kHz), added new planners (AORRTC, BLIT*, TRRT*), and deprecated OMPL.app. Status: maintained (2.0.2 released 2026-08-14). Source: https://github.com/ompl/ompl/releases/tag/2.0.0 (paper: https://arxiv.org/abs/2605.29301)
- **cuRobo** — NVIDIA CUDA-accelerated robot library built on PyTorch, CUDA and Warp: GPU-parallel FK/IK, collision checking, trajectory optimization, geometric planning and GPU-native ESDF perception, scaling from single arms to humanoids. v0.8.0 is cuRoboV2, a major rewrite that breaks the v1 API; code written against v1 must pin the `v0.7.8` tag. Status: maintained (NVIDIA Labs, Apache-2.0, v0.8.0 released 2026-04-18). Source: https://github.com/NVlabs/curobo (paper: https://arxiv.org/abs/2603.05493)
- **Tesseract** — ROS-Industrial's lightweight motion-planning environment (Eigen/Boost/Orocos deps only), pairs with the TrajOpt trajectory optimizer; core is ROS-agnostic with a standalone Python package. Status: maintained. Source: https://github.com/tesseract-robotics/tesseract

## Trajectory generation
- **Ruckig** — real-time, jerk-constrained, time-optimal trajectory generation from any initial state to a target waypoint; jointly computes path and time parametrization for intermediate waypoints (RSS 2021 paper). Status: maintained. Source: https://github.com/pantor/ruckig
- **TOPP-RA (toppra)** — reachability-analysis-based time-optimal path parameterization given joint velocity/acceleration/tool-Cartesian constraints; `pip install toppra`. Status: maintained. Source: https://github.com/hungpham2511/toppra

## Dynamics / rigid-body libraries
- **Pinocchio** — fast rigid-body dynamics (RNEA, ABA, CRBA) with analytical derivatives, built on Eigen + FCL, Python bindings via Conda; the base layer under Pink and many optimization-based IK/planning stacks. Status: maintained. Source: https://github.com/stack-of-tasks/pinocchio
- **RBDL** — C++ rigid-body dynamics library (ABA/RNEA/CRBA, contact/collision constraints) originally from Heidelberg University's ORB group; the ORB-HD fork (rbdl-orb) is the older line and has not been updated since 2022. The upstream rbdl/rbdl is packaged in vcpkg (port rbdl 3.3.1). Status: low activity (upstream rbdl/rbdl last release v3.3.1 2024-08-23, last push 2025-06-09; the ORB-HD fork has had no push since 2022-04-20, last release v3.1.3 2021-09-30). Source: https://github.com/rbdl/rbdl (fork: https://github.com/ORB-HD/rbdl-orb)
- **MuJoCo** — contact-rich physics engine with soft-contact/implicit integration widely treated as the reference for manipulation and grasping dynamics; monthly release cadence, maintained by Google DeepMind. Also used standalone as a simulator, with MJX for JAX/GPU parallelism and MuJoCo Warp (GPU-accelerated, maintained by Google DeepMind and NVIDIA as part of Newton; v3.14.0 on 2026-09-22). Status: maintained (MuJoCo 3.14.0 released 2026-09-22). Source: https://github.com/google-deepmind/mujoco ; MuJoCo Warp: https://github.com/google-deepmind/mujoco_warp

## Real-time servoing / teleop
- **MoveIt Servo** — collision- and singularity-aware real-time Cartesian/joint servoing for ROS 2 manipulators; consumes `TwistStamped` from gamepads, VR controllers, 6-DoF mice, or other nodes. Status: maintained, part of moveit2. Source: https://moveit.picknik.ai/humble/doc/examples/realtime_servo/realtime_servo_tutorial.html
- **GELLO** — low-cost, 3D-printed, kinematically-isomorphic leader-follower teleoperation controller (UC Berkeley) for collecting imitation-learning demonstrations; supports Franka, UR, xArm, and others. Status: maintained (515 stars, ongoing ROS 2 support work). Source: https://github.com/wuphilipp/gello_software
- **ALOHA** — low-cost open-source bimanual teleoperation hardware + software (master-puppet arms) for fine-manipulation demonstration collection (Stanford); ALOHA 2 is the enhanced-hardware follow-up. Status: no commits since 2024-04-19 (ROS 2 support still marked in-progress in the README). Source: https://github.com/tonyzhaozh/aloha ; ALOHA 2 paper: https://arxiv.org/pdf/2405.02292

## Hardware interfaces and drivers
- **ros2_control / ros2_controllers** — the ROS 2 control framework that stage 3 of the pipeline builds on: ros2_control provides the controller manager and hardware components of type Actuator, Sensor and System, and ros2_controllers provides ready-made controllers such as `joint_trajectory_controller` (executes joint-space trajectories on a group of joints). A hardware component can be run in its own thread with `is_async="true"` (default false), so a component whose read is slow does not block the control loop; this is documented in the Rolling docs, so check that your distro supports it. Status: maintained (ros2_control tag 6.10.1, ros2_controllers tag 6.9.0, both repos pushed 2026-10-01). Source: https://github.com/ros-controls/ros2_control ; https://github.com/ros-controls/ros2_controllers ; https://control.ros.org/master/doc/ros2_control/hardware_interface/doc/asynchronous_components.html
- **feetech_ros2_driver** — ros2_control hardware interface for Feetech serial-bus servos; per-joint `id` (required, in URDF), `homing_offset` (written to servo EEPROM), `range_min`/`range_max` and `p_coefficient`/`i_coefficient`/`d_coefficient`, set in URDF `<param>` tags or in a YAML `joint_config_file` (YAML wins when both are given). The old `offset` parameter is deprecated and ignored (migrate with `homing_offset = old_offset - 2048`). The user guide points to ros2_so_arm100 and so101-ros-physical-ai as example integrations. Status: maintained (BSD-3-Clause, CI on Humble, Jazzy and Rolling; last commit 2026-07-21, tag 0.2.2 pushed 2026-09-21, no GitHub release object). Source: https://github.com/ros-physical-ai/feetech_ros2_driver
- **dynamixel_hardware_interface** — ROBOTIS's ros2_control hardware plugin for Dynamixel motors, configured through ros2_control URDF parameters (port, `baud_rate`, `error_timeout_ms`, per-motor interfaces); used in its OpenManipulator-X example. Status: maintained by the manufacturer (release 1.5.2 on 2026-03-13; supports ROS 2 Humble, Jazzy and Rolling). Source: https://github.com/ROBOTIS-GIT/dynamixel_hardware_interface

## Simulators for manipulation
- **Isaac Sim / Isaac Lab** — NVIDIA RTX-based photorealistic simulation plus a GPU-parallel robot-learning framework (RL/IL/motion planning) with 30+ prebuilt environments and thousands of parallel envs. Status: maintained (v3.0.0-EA early access released 2026-09-16, built for Isaac Sim 6.1 with a Newton physics backend; General Availability targeted toward the end of October 2026 per the release notes), arXiv paper 2511.04831. Source: https://github.com/isaac-sim/IsaacLab/releases/tag/v3.0.0-EA
- **Genesis** — unified multi-physics simulation platform (rigid body, MPM, SPH, FEM, PBD) with a Pythonic interface and generative data engine; reports extreme simulation throughput (millions of FPS for a single arm on one RTX 4090). Now backed by Genesis AI. Status: maintained, ~30k stars. Source: https://github.com/Genesis-Embodied-AI/Genesis
- **Gazebo (gz-sim)** — general-purpose open-source robotics simulator, the long-standing ROS-ecosystem default, with multi-physics-engine support and Gazebo Fuel model libraries. Status: maintained (Intrinsic-led). Source: https://github.com/gazebosim/gz-sim

## China-market / Chinese-language ecosystem
- **AgileX PiPER (松灵机器人)** — Dongguan-based AgileX Robotics' desktop dual-arm teleoperation platform (four 6-DoF arms, depth cameras, controllers) for embodied-AI data collection, imitation learning, and VLA research; ships with development interfaces/sample programs. Company also recently released a 7-DoF NERO arm (listed as "NERO-7 DoF" in the product-page navigation). Its ROS 2 driver is the unified `agx_arm_ros` (Humble and Jazzy marked Pass) on the `pyAgxArm` SDK, which supports Piper and Nero; the older `piper_ros` README is the ROS 1 Noetic branch. Status: commercial, active product line (agx_arm_ros last push 2026-09-21). Source: https://www.agilex.ai/product/69cce7c9f70ae516ed948dc9 ; https://github.com/agilexrobotics/agx_arm_ros ; https://github.com/agilexrobotics/pyAgxArm
- **Unitree Z1 SDK** — Unitree Robotics' official C++/Python SDK for its Z1 6-DoF manipulator arm, BSD-3-licensed. Status: maintained by manufacturer. Source: https://github.com/unitreerobotics/z1_sdk
- **Dummy-Robot** — popular Chinese open-source mini robotic-arm project (peng-zhihui): full hardware, closed-loop stepper-driven firmware, and Unity-based host software, with inverse kinematics and CAN-bus control. Status: open-source hobby/reference project, ~15.3k GitHub stars. Source: https://github.com/peng-zhihui/Dummy-Robot

## Notable recent research directions (arXiv-verified)
- **Diffusion Policy** (Chi, Xu, Feng et al., 2023) — represents a visuomotor manipulation policy as a conditional denoising-diffusion process; now a standard imitation-learning baseline. arXiv:2303.04137. Source: https://arxiv.org/abs/2303.04137
- **ACT / fine-grained bimanual manipulation** (Zhao et al., 2023) — action-chunking transformer paired with the low-cost ALOHA hardware for fine bimanual manipulation from demonstrations. arXiv:2304.13705. Source: https://arxiv.org/abs/2304.13705
- **OpenVLA** (Kim, Pertsch, Karamcheti et al., 2024) — 7B-parameter open-source vision-language-action model trained on 970k robot demonstrations, fine-tunable on consumer GPUs via LoRA. arXiv:2406.09246. Source: https://arxiv.org/abs/2406.09246
- **Octo** (Octo Model Team et al., 2024) — open-source generalist transformer policy trained on 800k Open X-Embodiment trajectories, finetunable to new sensors/action spaces within hours. arXiv:2405.12213. Source: https://arxiv.org/abs/2405.12213
- **π0** (Physical Intelligence — Black, Brown, Driess et al., 2024) — flow-matching vision-language-action model built on a pretrained VLM, trained across single-arm, dual-arm, and mobile-manipulator platforms. arXiv:2410.24164. Source: https://arxiv.org/abs/2410.24164
