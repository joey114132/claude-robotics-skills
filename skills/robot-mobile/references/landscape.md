# Mobile Robot Navigation Landscape — verified snapshot

**Verified: 2026-10-02 (changed entries and link fixes; rest 2026-08-05).** Entries were confirmed against live sources on this date — re-verify anything before relying on it if this snapshot is more than ~6 months old.

## Base drive control

- **ros2_controllers drive controllers** — ros2_control controllers that turn body velocity commands into wheel commands: `diff_drive_controller`, the mecanum and omni-wheel drive controllers, the steering-controller library (bicycle, tricycle, Ackermann), and a tricycle controller. `diff_drive_controller` computes odometry from hardware feedback and publishes it, with task-space velocity, acceleration and jerk limits and an automatic stop after a command time-out. Status: maintained (repo pushed 2026-10-01, released in rosdistro for Jazzy, Kilted and Lyrical). Source: https://control.ros.org/lyrical/doc/ros2_controllers/doc/controllers_index.html and https://github.com/ros-controls/ros2_controllers

## SLAM packages

- **slam_toolbox** — 2D lifelong SLAM/localization for potentially massive maps; the currently supported ROS 2 SLAM library (built by Steve Macenski). Status: maintained. Source: https://github.com/SteveMacenski/slam_toolbox
- **Cartographer / cartographer_ros** — 2D/3D real-time SLAM across multiple sensor configs. The upstream cartographer-project repositories are idle (`cartographer` last pushed 2024-01-05). ROS 2 packages are released from the `ros2` branches of the ros2/cartographer and ros2/cartographer_ros forks, which last saw small commits in 2025-05. Status: low activity, still released for Jazzy, Kilted and Lyrical. Source: https://github.com/ros2/cartographer_ros and https://github.com/ros/rosdistro/blob/master/lyrical/distribution.yaml
- **RTAB-Map (rtabmap_ros)** — RGB-D/stereo/LiDAR graph-based SLAM with appearance-based loop closure; the ROS 2 wrapper keeps ROS 1 parameter and topic names, requires ROS 2 Humble at minimum, and lists Jazzy, Kilted and Lyrical. Status: maintained. Source: https://github.com/introlab/rtabmap_ros
- **GLIM** — range-based 3D mapping framework using multi-scan registration on factor graphs, with optional GPU acceleration and an interactive map-correction interface; works with spinning lidars, non-repetitive-scan lidars (Livox Avia, MID360), solid-state lidars and RGB-D cameras; ROS 2 through `glim_ros2`, tested on Ubuntu 22.04/24.04 and Jetson Orin (JetPack 6.1). Status: maintained (repo pushed 2026-09-06). Source: https://github.com/koide3/glim

## Localization

- **nav2_amcl** — Adaptive Monte Carlo Localization particle filter that localizes the robot in a static map; ships as part of Nav2. Status: maintained. Source: https://docs.nav2.org/lyrical/configuration_and_development/configuration_guide/others/configuring_amcl/
- **robot_localization** — EKF/UKF-based sensor fusion (IMU, wheel odometry, GPS, etc.) for continuous state estimation; commonly paired with or substituted for AMCL. Status: maintained. Source: https://github.com/cra-ros-pkg/robot_localization

## Nav2 core & plugins

- **Nav2 (navigation2)** — production-grade ROS 2 navigation framework (perception, planning, control, localization, behaviors) that its docs describe as trusted by 300+ companies; the professionally supported successor of the ROS Navigation Stack. Docs list Lyrical and Jazzy as actively supported and Kilted and Humble as maintained. Status: maintained. Source: https://docs.nav2.org/lyrical/
- **Nav2 Lyrical (1.5.x)** — first Nav2 release for ROS 2 Lyrical Luth (tag 1.5.0 on 2026-08-04, 1.5.1 on 2026-08-12, 1.5.2 on 2026-09-16; announcement post 2026-08-25). New: `nav2_ros_common`, an MPPI open-loop mode and plugin motion models, the `PauseResumeController` BT node, a Vector Object Server, an Adaptive Goal Checker, Dynamic Window Pure Pursuit in RPP, a much faster inflation layer, and Collision Monitor toggles and exclusion zones. The Kilted-to-Lyrical migration is breaking: plugins and custom nodes move to `nav2::LifecycleNode`, controller plugins replace `setPlan` with `newPathReceived`, BT Navigator blackboard ID parameters move under each navigator's namespace, and the RoundRobin `wrap_around` parameter defaults to false. Status: maintained. Source: https://discourse.openrobotics.org/t/nav2-lyrical-release-key-features/57666 and https://docs.nav2.org/lyrical/configuration_and_development/migration_guides/kilted/Kilted/
- **nav2_regulated_pure_pursuit_controller** — pure-pursuit local trajectory controller with regulation heuristics for velocity/collision constraints; best for exact path-following without dynamic-obstacle deviation. Status: maintained. Source: https://github.com/ros-navigation/navigation2/blob/main/nav2_regulated_pure_pursuit_controller/README.md
- **nav2_mppi_controller** — Model Predictive Path Integral local controller with plugin-based critics, adaptive collision avoidance; runs 50+ Hz on a modest 4th-gen i5; supports diff-drive, omni, and Ackermann robots. Status: maintained. Source: https://github.com/ros-navigation/navigation2/tree/main/nav2_mppi_controller
- **nav2_smac_planner** — templated A*-family global planner family: `SmacPlanner2D` (circular diff/omni robots), `SmacPlannerHybrid` (car/ackermann/legged, Hybrid-A*), `SmacPlannerLattice` (arbitrary-shaped vehicles, State Lattice). Status: maintained. Source: https://github.com/ros-navigation/navigation2/tree/main/nav2_smac_planner
- **nav2_bt_navigator / nav2_behavior_tree** — behavior-tree orchestration layer: the BT Navigator implements the NavigateToPose, NavigateThroughPoses and other task interfaces as a Behavior Tree-based implementation of navigation. Application logic is centralized in the tree, with independent task servers that only communicate data over the tree. Status: maintained. Source: https://docs.nav2.org/lyrical/getting_started/navigation_concepts/behavior_trees/ and https://docs.nav2.org/lyrical/configuration_and_development/configuration_guide/core_servers/configuring_bt_navigator/
- **nav2_collision_monitor** — node that checks laser scan, point cloud, range (IR/sonar) or costmap data against configurable polygon zones with Stop, Slowdown and time-to-collision Approach models; VelocityPolygon switches zones by command velocity. It bypasses the costmap and trajectory planners and filters the `cmd_vel` coming out of the Controller Server. Its README says it does not provide hard real-time safety certification and is meant for users without safety-rated scanners or controllers. Status: maintained. Source: https://github.com/ros-navigation/navigation2/blob/main/nav2_collision_monitor/README.md

## Docking / charging

- **Nav2 docking server (`opennav_docking`, in the `nav2_docking` directory of navigation2)** — docking task server with pluggable `ChargingDock` and `NonChargingDock` plugins and a database of many docks of different types; migrated into Nav2 core in June 2024 (the old open-navigation repo now serves only Humble). With `navigate_to_staging_pose = True`, call `DockRobot` from your application-level tree, not from inside a Nav2 BT. Status: maintained. Source: https://docs.nav2.org/lyrical/tutorials/general_tutorials/using_docking/ and https://github.com/ros-navigation/navigation2/tree/main/nav2_docking

## Sensor drivers of note

- **rplidar_ros (Slamtec)** — official ROS driver for the RPLIDAR series (A1/A2/A3/S1/S2/S3/T1); ROS 2 support on the `ros2` branch. Status: maintained. Source: https://github.com/Slamtec/rplidar_ros/tree/ros2
- **velodyne (ros-drivers/velodyne)** — ROS 2 packages for Velodyne 3D LiDARs (64E S2/S2.1/S3, 32E, 32C, VLP-16). Status: maintained. Source: https://github.com/ros-drivers/velodyne/tree/ros2
- **realsense-ros** — official RealSense ROS 2 wrapper (`realsense2_camera`) for D400-series depth cameras, with calibration-config and safety-preset services for specific camera modules (D500 example tables); the README now lives under the realsenseai GitHub org and its distro badges run from Foxy to Rolling. Status: maintained. Source: https://github.com/realsenseai/realsense-ros

## Simulators for navigation

- **Gazebo + ros_gz** — modern Gazebo simulator with a Nav2 SDF setup guide; `ros_gz_bridge` exchanges messages between ROS 2 and Gazebo Transport. Pairings per the ros_gz README: Jazzy with Harmonic (binaries on packages.ros.org), Kilted with Ionic, Lyrical with Jetty (binaries); Lyrical with Harmonic or Ionic is source-only. Status: maintained. Source: https://github.com/gazebosim/ros_gz and https://docs.nav2.org/lyrical/configuration_and_development/first_time_robot_setup_guide/sdf/setup_sdf/
- **webots_ros2 (Cyberbotics)** — official ROS 2 integration for the Webots simulator, with a "Navigate TurtleBot3" example in its wiki; last GitHub release 2025.0.0 (2025-02-18), repo still pushed in 2026-09, and rosdistro lists 2025.0.1 for Kilted and Lyrical. Status: maintained, slow release cadence. Source: https://github.com/cyberbotics/webots_ros2 and https://github.com/cyberbotics/webots_ros2/wiki/Examples
- **NVIDIA Isaac Sim (ROS 2 Navigation tutorials)** — Omniverse-based simulator with documented single- and multi-robot Nav2 navigation tutorials; Isaac Sim 6.1.0 was released 2026-09-10 and the 5.1.0 docs now carry an "Unsupported release" banner. Status: maintained (commercial platform, free tier). Source: https://docs.isaacsim.omniverse.nvidia.com/6.1.0/ros2_tutorials/robot_control/tutorial_ros2_multi_navigation.html and https://github.com/isaac-sim/IsaacSim/releases
- **nav2_loopback_sim** — standalone non-physical "loopback" simulator that stands in for a physics simulator (Gazebo/Bullet/Isaac Sim) or real hardware for fast Nav2-only testing. Status: maintained. Source: https://docs.ros.org/en/jazzy/p/nav2_loopback_sim/
