# Multi-Robot & Fleet Landscape — verified snapshot

**Verified: 2026-10-02 (changed entries and link fixes; rest 2026-08-05).** Entries were confirmed against live sources on this date — re-verify anything before relying on it if this snapshot is more than ~6 months old.

## Open-RMF components & status

- **Open-RMF (root repo)** — "the Open-RMF platform for multi-fleet robot management"; vendor-agnostic orchestration for heterogeneous robot fleets sharing space, lifts, doors, and other building infrastructure. Actively supports ROS 2 Humble, Jazzy, Kilted, and Rolling with binary packages and nightly Docker builds. Status: maintained. Source: https://github.com/open-rmf/rmf
- **rmf_ros2** — internal ROS 2 infrastructure for RMF, including the `rmf_fleet_adapter` package (the C++ API fleets integrate against); last updated Jul 29, 2026 at verification time. Status: maintained. Source: https://github.com/open-rmf/rmf_ros2
- **rmf_traffic** — core algorithms and data structures for scheduling and negotiating mobile-robot traffic between multiple agents. Status: maintained. Source: https://github.com/open-rmf/rmf_traffic
- **rmf-web** — TypeScript web dashboard for visualizing and controlling Open-RMF deployments; updated Aug 3, 2026 at verification time. Status: maintained. Source: https://github.com/open-rmf/rmf-web
- **rmf_demos** — reference demonstrations/simulations of Open-RMF deployments. Status: maintained. Source: https://github.com/open-rmf/rmf_demos
- **free_fleet** — Python Open-RMF fleet adapter for robots that expose a Nav2 or Nav1 stack; it uses Zenoh bridges between each robot and the adapter, expects each robot's navigation stack to stay non-namespaced with the robot name applied as the namespace on its Zenoh bridge, and documents Ubuntu 24.04 with ROS 2 Jazzy, mostly tested on rmw_cyclonedds; updated Jul 28, 2026 at verification time. Status: maintained. Source: https://github.com/open-rmf/free_fleet
- **fleet_adapter_template** — starting-point template repo for integrating a new robot fleet with Open-RMF; updated Jul 11, 2026 at verification time. Status: maintained. Source: https://github.com/open-rmf/fleet_adapter_template
- **next_gen_prototype** — prototype repo for the next generation of Open-RMF; its README calls it "a temporary space for drafting prototype data structures and design documents for the next generation of Open-RMF" and lists ROS 2 Jazzy and the latest Rust compiler as prerequisites. A GSoC 2026 write-up dated 2026-08-25 says the project is moving from a monolithic stack toward a "horizontal" architecture of smaller ROS 2 nodes that can be replaced independently (Destination Server, Path Server, Plan Executor). That GSoC work merged an optional reservation-aware destination server with parking zones for robots whose requested goal is already claimed (PR #25, merged 2026-07-01) and a layered global occupancy map that shares robot-detected obstacles with the central path server (PR #36, merged 2026-08-20). The write-up itself says a production Nav2 costmap observation node is still missing. Status: prototype. Source: https://github.com/open-rmf/next_gen_prototype and https://discourse.openrobotics.org/t/next-gen-open-rmf-traffic-management/57646
- **osrf/rmf_core (legacy)** — the original centralized RMF scheduling repo; archived by the owner on Jul 22, 2021 and now read-only. Development moved to the `open-rmf` GitHub org (above). Status: archived/superseded — do not build against this repo. Source: https://github.com/osrf/rmf_core

## Fleet management systems (open + commercial + China-market)

- **Robofleet** — open-source, web-based multi-robot control/visualization for ROS, presented at IROS 2021; robots run a client that exchanges data with a central server. Status: research/low-activity open source. Source: https://github.com/ut-amrl/robofleet
- **RobotFleet** — open-source framework for centralized multi-robot task planning/scheduling that wraps robots as containerized services and leverages LLMs for planning. Status: research. Source: https://arxiv.org/pdf/2510.10379
- **Seer Robotics (SEER Intelligent Technology)** — China-based AGV/AMR navigation-controller and fleet-software platform vendor; SRC-series controllers reported to power 200+ AGV/AMR brands and hold #1 global robot-controller market share (24.8% global / 45.2% China, cited for 2025). Status: commercial. Source: https://www.mobile-robots.com/manufacturer/seer-robotics/
- **Geek+ (极智嘉)** — Beijing-headquartered AMR/warehouse-robotics vendor; self-developed dispatch system reported to process ~10k instructions/sec and coordinate 5,000+ robots per warehouse; reported #1 global AMR market share for 6 consecutive years. Status: commercial. Source: https://www.geekpark.net/news/350876
- **Hikrobot** — machine-vision and mobile-robot vendor (Hangzhou Hikrobot Co., Ltd., founded 2016); its mobile-robot pages list LMR, FMR and CMR product lines and name iWMS-1000 and RCS-2000 among its AMR solutions. Status: commercial. Source: https://www.hikrobotics.com/en/mobilerobot/ and https://www.hikrobotics.com/en/about
- **Youibot (YOUIFleet)** — Shenzhen-based AMR maker; YOUIFleet fleet-management software offers dynamic task scheduling, path planning, and congestion prediction for narrow-aisle warehouse scenarios. Status: commercial. Source: https://en.youibot.com/products-category/youifleet.html
- **Quicktron** — Alibaba-backed AGV vendor focused on high-throughput e-commerce fulfillment/sorting; reports 1,000+ enterprise customers across 30+ countries. Status: commercial. Source: https://www.mobile-robots.com/manufacturer/quicktron/

## Interoperability standards

- **VDA 5050 (v3.0.0)** — open, vendor-neutral communication interface between a central fleet control system and mobile robots from different manufacturers, developed by the VDA and VDMA under the technical supervision of the Institute for Material Handling and Logistics (IFL) at KIT. The specification's message protocol is MQTT (3.1.1 minimum). Version 3.0 adds a zone concept for free navigation and a path-sharing mechanism so freely navigating robots can report their paths to the central control. The spec scope explicitly excludes traffic management logic (routing, prioritization, congestion handling, deadlock resolution), so it defines the interface and not the traffic logic. Status: maintained (3.0.0 released 2026-03-18 on GitHub, repo pushed 2026-09-28; VDA press release dated 2026-04-20). Source: https://github.com/VDA5050/VDA5050 and https://www.vda.de/en/press/press-releases/2026/260421_PM_VDA_5050_EN
- **vda5050_core** — Apache-2.0 C++17 library from the ROS-Industrial organization for implementing VDA 5050 on AGVs, AMRs and fleet-control masters: data structures for the message types, MQTT transport, Layout Interchange Format support, optional ROS 2 interfaces (Humble/Jazzy) and Python bindings (pybind11); the repo also ships an Open-RMF migration guide. Status: pre-release (latest tag 0.1.0rc2, no GitHub release yet; README says "under active development"). Source: https://github.com/ros-industrial/vda5050_core

## Multi-robot middleware / discovery at scale

- **rmw_zenoh** — ROS 2 RMW implementation built on the Zenoh protocol; a Tier-1 middleware starting with ROS 2 Kilted Kaiju per Open Robotics' release announcement (the Tier-1 tracking issue #265 is closed). Distro branches exist for Humble, Jazzy, Kilted, Lyrical and Rolling, and rosdistro lists the package for Humble, Jazzy and Kilted. Nodes find each other through a Zenoh router (`ros2 run rmw_zenoh_cpp rmw_zenohd`) because multicast discovery is off by default. Per the README, Humble and newer distros cannot exchange data: type hashes, introduced in Iron, are embedded in the Zenoh key expressions, so participants remain discoverable but messages are silently dropped. Status: maintained. Source: https://github.com/ros2/rmw_zenoh and https://www.openrobotics.org/blog/2025/5/23/ros-2-kilted-kaiju-released
- **Fast DDS Discovery Server** — centralized discovery mode for DDS/ROS 2 (vs. default peer-to-peer multicast discovery); the Husarnet write-up says peer-to-peer discovery over a VPN scales with the square of the device count, that adding a device needs no XML change on existing participants, and that redundant discovery servers can run in parallel. Status: maintained. Source: https://husarnet.com/blog/ros2-dds-discovery-server
- **When Discovery Becomes a Storm: A ROS 2 Discovery Model for Wireless Robotic Networks** (arXiv:2608.02242) — closed-loop model showing that on a shared wireless channel, delayed or lost DDS discovery messages expire reliability timers, and the retransmissions add contention and delay further discovery, escalating into a discovery storm; validated over 1,350 runs on 90 topologies, and a response-aware discovery policy cuts mean discovery completion time by 25.3% to 39.7%. Status: research, submitted 2026-08-03. Source: https://arxiv.org/abs/2608.02242

## Task allocation research (arXiv)

- **Very Large-scale Multi-Robot Task Allocation in Challenging Environments via Robot Redistribution** (arXiv:2506.07293) — MRTA in obstacle-dense/narrow-passage environments using a Generalized-Voronoi-Diagram roadmap to minimize makespan while avoiding collisions/deadlocks. Status: research. Source: https://arxiv.org/abs/2506.07293
- **Uncertainty-Aware Multi-Robot Task Allocation With Strongly Coupled Inter-Robot Rewards** (arXiv:2509.22469) — market-based decentralized MRTA that optimizes coupled team rewards under task-requirement uncertainty, with a polynomial-time decentralized solution. Status: research. Source: https://arxiv.org/abs/2509.22469
- **Efficient Human-Aware Task Allocation for Multi-Robot Systems in Shared Environments** (arXiv:2508.19731) — incorporates human motion patterns into MRTA decision-making for human-populated workspaces. Status: research. Source: https://arxiv.org/abs/2508.19731
- **Large Language Models for Multi-Robot Systems: A Survey** (arXiv:2502.03814) — survey categorizing LLM integration into multi-robot systems across high-level task allocation, mid-level motion planning, low-level action generation, and human intervention. Status: research. Source: https://arxiv.org/abs/2502.03814
