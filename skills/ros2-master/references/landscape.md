# ROS 2 Ecosystem Landscape — verified snapshot

**Verified: 2026-10-02 (changed entries and link fixes; rest 2026-08-05).** Entries were confirmed against live sources on this date — re-verify anything before relying on it if this snapshot is more than ~6 months old.

Entry format: **Name** — one-line what-it-is. Status: maintained / research / commercial. Source: `<url>`

## Active distros (from REP-2000 + release docs)

REP-2000 (fetched live) covers all releases through Kilted Kaiju; per the REP itself, platform/EOL info for releases after Kilted is published in each release's own documentation rather than the REP. Source: https://reps.openrobotics.org/rep-2000/

- **Jazzy Jalisco** — LTS, released May 2024, EOL May 2029. Status: maintained (LTS). Source: https://reps.openrobotics.org/rep-2000/
- **Kilted Kaiju** — non-LTS (1.5-year support), released May 2025, EOL November 2026. Status: maintained (approaching EOL). Source: https://reps.openrobotics.org/rep-2000/
- **Lyrical Luth** — LTS, released May 22, 2026, supported through May 2031. Newest ROS 2 distro; per REP-2000's own note, its platform/EOL details live in its release docs rather than the REP table. Tier 1 platforms: Ubuntu 26.04 (Resolute) amd64/arm64 and Windows 11 (VS 2022) amd64; Tier 2 RHEL 10; Tier 3 includes Ubuntu 24.04 Noble, macOS, Debian Trixie, OpenEmbedded. Headline changes: a Callback Group Events Executor (announcement claims 10–15% lower CPU than existing executors), `AsyncNode` bringing asyncio to rclpy, and `rosidl::Buffer` replacing `std::vector<uint8_t>` to enable zero-copy GPU data transfer. Status: maintained (current LTS). Source: https://discourse.openrobotics.org/t/ros-2-lyrical-luth-released/55021 (release announcement; the docs.ros.org mirror is behind an Anubis anti-bot gate and may not fetch)
- **Humble Hawksbill** — LTS, released May 2022, EOL May 2027 — still within support window but past its midpoint; plan migrations off it. Status: maintained (LTS, aging). Source: https://reps.openrobotics.org/rep-2000/
- **Rolling Ridley** — the rolling development distro, released June 2020, no fixed EOL (continuously developed; always tracks the next release). Status: maintained (dev target only, not for production pins). Source: https://reps.openrobotics.org/rep-2000/
- **Iron Irwini** — EOL'd November 2024. Do not start new work on it. Status: EOL. Source: https://reps.openrobotics.org/rep-2000/

## Middleware (DDS implementations + Zenoh)

- **Fast DDS (eProsima)** — the default RMW implementation (`rmw_fastrtps_cpp`) across every currently supported distro except EOL Galactic. Status: maintained (default). Source: https://fast-dds.docs.eprosima.com/en/latest/fastdds/ros2/ros2.html
- **Cyclone DDS (Eclipse)** — alternative Tier-1 DDS RMW (`rmw_cyclonedds_cpp`), used as the default only in the EOL Galactic distro; commonly swapped in for its lower resource footprint. Status: maintained. Source: https://github.com/ros2/rmw_cyclonedds
- **rmw_zenoh** — non-DDS RMW built on the Zenoh pub/sub/query protocol; installable as an alternative from Jazzy and a Tier 1 RMW on all architectures in Kilted (REP-2000: "rmw_zenoh_cpp | Eclipse Zenoh | Tier 1 | All Platforms | All Architectures") and in Lyrical (Zenoh 1.8.0), targeting constrained/fog/cloud deployments where DDS discovery overhead is a problem. DDS remains the default (Lyrical's platform page: "The default middleware in ROS Lyrical is rmw_fastrtps_cpp"), so Zenoh is an opt-in alternative that needs a running Zenoh router because multicast discovery is disabled by default (README). Lyrical's rosidl::Buffer zero-copy path may be used with rmw_fastrtps_cpp or rmw_zenoh_cpp (Lyrical release notes). Repo carries formal Quality Declarations and ships binaries for Tier-1 platforms, with per-distro branches. Status: maintained (official alternative). Source: https://github.com/ros2/rmw_zenoh (also https://reps.openrobotics.org/rep-2000/, https://github.com/ros2/ros2_documentation/blob/rolling/source/Releases/lyrical/supported-platforms.rst and https://github.com/ros2/ros2_documentation/blob/rolling/source/Releases/Release-Lyrical-Luth.rst)

## ros2_control

- **ros2_control** — the standard actuator-control framework (hardware interfaces, controller manager, JointTrajectoryController etc.); maintainer count has doubled and the project is now under OSRA (Open Source Robotics Alliance) governance. MoveIt 2 only plans motion — ros2_control is what actually executes it on hardware. **Distro coverage as of 2026-10-02: the control.ros.org version menu lists Kilted (latest), Jazzy and Humble as stable and Rolling and Lyrical as in development, but Lyrical binaries exist.** ros-lyrical-ros2-control went from 6.7.1 to 6.8.0 in the 2026-08-07 sync and from 6.9.0 to 6.10.1 in the 2026-09-18 sync, alongside MoveIt 2.15.2, gz_ros2_control 3.0.9 and ros_gz 3.0.10. The docs site lags the packages, so pin by checking the Lyrical sync posts or rosdistro, not the docs version selector. Status: maintained (actively growing). Source: https://control.ros.org/rolling/doc/release_notes/release_notes.html (also https://discourse.openrobotics.org/t/new-packages-for-lyrical-2026-09-18/58251 and https://discourse.openrobotics.org/t/new-packages-and-patch-release-for-lyrical-2026-08-07/57230)

## Notable ecosystem tools / shifts

- **Nav2** — the industry-standard ROS 2 navigation stack (its site calls it the professionally-supported successor of the ROS Navigation Stack and says it is trusted by 300+ companies), with Open Navigation providing professional services. Lyrical release announced 2026-08-25 (new nav2_ros_common package, MPPI additions, a redesigned docs site with a separate version per distro). Status: maintained (commercial-backed). Source: https://docs.nav2.org/rolling/ (also https://discourse.openrobotics.org/t/nav2-lyrical-release-key-features/57666 and https://github.com/ros-navigation/navigation2)
- **MoveIt 2** — the standard ROS 2 motion-planning framework; plans trajectories that ros2_control then executes via the JointTrajectoryController interface. Status: maintained. Source: https://moveit.ai/about/distribution/
- **Gazebo Jetty** — LTS release of Gazebo, Sept 2025 to May 2031, and the recommended pairing for ROS 2 Lyrical and Rolling. Gazebo Ionic (Sept 2024, non-LTS, the recommended pairing for Kilted and only a possible one, with caution, for Lyrical and Rolling) reaches EOL in December 2026, and the Gazebo team recommends upgrading to Jetty. Status: maintained (LTS, Lyrical pairing). Source: https://gazebosim.org/docs/latest/ros_installation/ (also https://gazebosim.org/docs/latest/releases/ and the Ionic EOL notice of 2026-09-09: https://discourse.openrobotics.org/t/gazebo-ionic-reaching-end-of-life-in-december-2026/57981)
- **Gazebo Harmonic** — LTS release of "new" Gazebo (the Ignition-lineage rewrite, distinct from the retired "classic" Gazebo); released Sept 2023, EOL May 2029. It is the recommended pairing for ROS 2 Jazzy and not the default for every distro: Humble pairs with Fortress, Kilted with Ionic, Lyrical with Jetty. Harmonic is only a possible pairing, with caution, for Humble, Kilted, Lyrical and Rolling. Status: maintained (LTS, Jazzy pairing). Source: https://gazebosim.org/docs/latest/releases/ (pairing table: https://gazebosim.org/docs/latest/ros_installation/)
- **Isaac Sim / Isaac Lab as a ROS 2 sim target** — NVIDIA's GPU-accelerated simulator with a ROS 2 bridge, used for photorealistic rendering and large-scale parallel RL (Isaac Sim 6.1.0, released 2026-09-10; Isaac Lab v3.0.0-EA, 2026-09-16, built for Isaac Sim 6.1). Its docs name Humble and Jazzy as the officially tested ROS 2 distros (Jazzy on Ubuntu 24.04 recommended); loading other natively installed distros is marked experimental, so do not assume it works with a ROS 2 distro other than Humble or Jazzy. Status: maintained (NVIDIA-backed). Source: https://docs.isaacsim.omniverse.nvidia.com/latest/installation/install_ros.html (releases: https://github.com/isaac-sim/IsaacSim/releases and https://github.com/isaac-sim/IsaacLab/releases)
- **mujoco_ros2_control** — ros2_control SystemInterface plugin that runs ROS 2 controllers against the MuJoCo simulator (MJCF or URDF-converted models, with sensor, RGB-D camera and lidar support), maintained in the ros-controls org; updated to 0.1.2-1 in the 2026-09-18 Lyrical sync, with CI across Humble, Jazzy, Kilted, Lyrical and Rolling. Status: maintained (young, 0.1.x). Source: https://github.com/ros-controls/mujoco_ros2_control (sync: https://discourse.openrobotics.org/t/new-packages-for-lyrical-2026-09-18/58251)
- **REP-158 (OpenUSD conventions for simulation asset interoperability)** — specifies OpenUSD schemas and an interoperability profile for robotics simulation assets (robots, sensors, environments, props), targeting Gazebo, Isaac Sim, Newton, Genesis, MuJoCo and O3DE and export formats such as glTF 2.0. The ROS PMC minutes of 2026-09-29 (posted 2026-09-30) record it as accepted, while the REP page still read "Status: Draft" (updated Jul 14, 2026) when fetched on 2026-10-02. Status: accepted per PMC minutes (REP page still shows Draft). Source: https://reps.openrobotics.org/rep-0158-2006/ (acceptance: https://discourse.openrobotics.org/t/ros-pmc-minutes-for-september-29-2026/58518)
