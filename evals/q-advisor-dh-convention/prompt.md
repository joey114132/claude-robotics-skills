expected_outcome: "The forward kinematics is wrong because the two sides use different DH conventions, not because of a numeric or unit bug. Craig's Introduction to Robotics (3rd ed.) uses the modified (proximal) convention, where link i-1 carries a_{i-1} and alpha_{i-1} and the transform is Rot_x(alpha_{i-1}) Trans_x(a_{i-1}) Rot_z(theta_i) Trans_z(d_i). Many vendor datasheets list standard (distal, 'classic') parameters, where the transform is Rot_z(theta_i) Trans_z(d_i) Trans_x(a_i) Rot_x(alpha_i), so a_i and alpha_i sit on the link after joint i and the frames are placed differently. Feeding a datasheet row i into Craig's formula as (alpha_{i-1}, a_{i-1}, d_i, theta_i) shifts every a and alpha by one index, so the error is a structural mismatch that grows with pose and cannot be fixed by tuning offsets. An expert answer names the convention mismatch, recommends either implementing the standard transform that matches the datasheet or converting the table to modified parameters (shift a and alpha by one index and re-derive frames and the tool transform), and suggests verifying against a known pose from the vendor. Source: https://en.wikipedia.org/wiki/Denavit%E2%80%93Hartenberg_parameters (modified/proximal versus classic/distal transform order and frame placement, noting that Craig 3rd ed. uses the modified convention)."

I'm writing forward kinematics in Python for a 6-DOF arm. The vendor datasheet gives a table of a, alpha, d and theta offset for each joint, and I built the link transform from Craig's Introduction to Robotics (Rot_x(alpha_{i-1}) Trans_x(a_{i-1}) Rot_z(theta_i) Trans_z(d_i)) and fed each datasheet row straight in as (alpha_{i-1}, a_{i-1}, d_i, theta_i). At the zero pose the tool position is already several centimetres off from the vendor's stated value, and the error changes as I move joints. I checked units (mm to m) and the joint sign directions and both look fine. What should I fix?
